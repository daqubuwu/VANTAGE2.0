# Оценка игрока: модель

Документ описывает, как считается одно число и четыре грани. Пишется до кода, потому что от него зависит половина сайта. Формула открыта пользователю: каждый показатель имеет тултип вида `math` с подстановкой реальных чисел.

## Что было в прототипе

Модель прототипа: четыре грани (Бой, Экономика, Лейнинг, Объекты), веса зависят от роли, каждая грань собирается из 2-5 частей, часть даёт перцентиль из поля `benchmarks` OpenDota.

```
safe:    бой .30  экономика .35  лейнинг .20  объекты .15
mid:     бой .35  экономика .25  лейнинг .25  объекты .15
off:     бой .30  экономика .20  лейнинг .30  объекты .20
support: бой .35  экономика .20  лейнинг .20  объекты .25
```

Структура правильная и сохраняется. Ломается одно: `benchmarks` от OpenDota — это перцентиль по итогу матча, одно число на игру. Из него нельзя получить оценку на 17-й минуте. А требование из последнего батча прототипа прямо говорит: оценка обязана меняться под ползунок.

## Что меняется

Оценка перестаёт зависеть от `benchmarks` и начинает считаться из временных рядов матча. `benchmarks` остаётся, но только как сверка итогового числа.

### Что вообще доступно во времени

| Данные | Есть ряд по минутам | Источник |
|---|---|---|
| Золото | да, `gold_t` | OpenDota, любой матч |
| Опыт | да, `xp_t` | OpenDota, любой матч |
| Ластхиты | да, `lh_t` | OpenDota, любой матч |
| Денаи | да, `dn_t` | OpenDota, распарсенный |
| Убийства с таймингом | да, `kills_log` | OpenDota, распарсенный |
| Смерти с таймингом | восстанавливаются из `kills_log` соперников | OpenDota, распарсенный |
| Покупки с таймингом | да, `purchase_log` | OpenDota, распарсенный |
| Объекты с таймингом | да, `objectives` | OpenDota, распарсенный |
| Урон по героям | нет, только итог | — |
| Урон по строениям | нет, только итог | — |
| Помощи | нет, только итог | — |
| Участие в файтах | нет, только итог | — |

Из этого следует жёсткое правило: **грань не показывает число, которого нет.** Часть, у которой нет ряда, при движении ползунка не пересчитывается, а помечается как «по итогу игры» и вычитается из веса грани до конца скраба. Никаких интерполяций итогового урона на минуту — это выдуманные данные.

### Состав граней с учётом времени

`T` — минута, на которой стоит ползунок. По умолчанию `T` = конец матча.

**Экономика** (полностью время-зависимая)
| Часть | Вес | Формула на T |
|---|---|---|
| Золото в минуту | 0.5 | `gold_t[T] / T` |
| Ластхиты в минуту | 0.3 | `lh_t[T] / T` |
| Доля нетворса команды | 0.2 | `gold_t[T] / Σ gold_t[T] по команде` |

**Бой** (время-зависимая на распарсенных матчах)
| Часть | Вес | Формула на T |
|---|---|---|
| Убийств в минуту | 0.3 | по `kills_log` до T |
| Смертей в минуту, инвертировано | 0.3 | по `kills_log` соперников до T |
| Опыт в минуту | 0.2 | `xp_t[T] / T`, прокси участия в размене |
| Урон по героям в минуту | 0.2 | только итог, помечается «по итогу» |

**Лейнинг** (заморожена после 10-й минуты по определению)
| Часть | Вес | Формула |
|---|---|---|
| Эффективность линии | 0.6 | `lane_efficiency_pct`, Stratz при отсутствии |
| Ластхиты к 10-й минуте | 0.4 | `lh_t[10]` против нормы роли |

При `T < 10` грань считается на текущей минуте и подписывается «линия ещё идёт». При `T >= 10` заморожена, ползунок её не двигает. Это честно: лейнинг закончился.

**Объекты**
| Часть | Вес | Формула на T |
|---|---|---|
| Башен и рошанов | 0.5 | по `objectives` до T |
| Урон по строениям | 0.3 | только итог, помечается «по итогу» |
| Доля урона по строениям | 0.2 | только итог, помечается «по итогу» |

Веса частей перенормируются на те части, что реально доступны. Если из грани выпало больше половины веса, грань показывает прочерк, а не приблизительное число.

## Нормировка: против чего сравниваем

Прототип брал перцентиль у OpenDota. Он существует только на итог, поэтому нужна своя опора.

Опора — **референсные кривые по роли и бракету**: для каждой роли и каждого диапазона ранга хранится медиана и 90-й перцентиль метрики по минутам. Строятся один раз офлайн скриптом, кладутся в репозиторий как статический JSON, обновляются раз в патч.

```
reference[bracket][role][metric] = { p50: number[], p90: number[] }
                                     индекс = минута
```

Перевод значения в долю от 0 до 1:

```
q(x, p50, p90) = clamp01( 0.5 + 0.5 * (x - p50) / max(1, p90 - p50) )
```

То есть медиана даёт 0.5, девяностый перцентиль даёт 1.0, всё ниже линейно падает к нулю. Функция без хвостов и без сигмоид: её видно в тултипе и она объясняется одной строкой.

Сбор референса: скрипт берёт публичные распарсенные матчи нужного бракета через OpenDota, набирает не меньше 400 наблюдений на каждую пару роль-минута, считает перцентили, режет минуты после 60-й. Пока референс не собран, используется `benchmarks` OpenDota на итоговой минуте, а ползунок для оценки блокируется с явной подписью. Заглушек с придуманными числами нет.

## Сборка

```
facetScore = Σ (partScore_i * partWeight_i) / Σ partWeight_i   по доступным частям
total      = Σ (facetScore_f * roleWeight_f) / Σ roleWeight_f  по доступным граням
score      = round(total * 100)
```

Буква — от `score`, пороги те же, что в прототипе.

## Доверие к числу

Оценка сопровождается уровнем доверия, а не показывается голой:

| Уровень | Условие | Как показывается |
|---|---|---|
| Полное | матч распарсен, референс есть, доступны все четыре грани | число крупно, без пометок |
| Частичное | выпала одна грань или часть частей «по итогу» | число крупно, рядом список того, чего не хватило |
| Низкое | матч не распарсен | число не показывается, вместо него кнопка запроса парсинга |

## Определение роли

Прототип определял роль эвристикой по фарму и стороне. Оставляем как основу, но приоритет отдаётся Stratz: у него есть поля `lane`, `position`, `role` из реальных данных матча. Эвристика включается, только когда Stratz недоступен или молчит по этому матчу.

## Тренд формы

График изменения оценки по последним N матчам. Отдельная точка на матч, поверх скользящее среднее по 10 играм. Ось Y в тех же 0-100, что и оценка. Матчи с низким доверием на графике помечаются полым маркером и в среднее не входят.

## Что модель не делает

- Не предсказывает исход матча (отклонено в анкете).
- Не выдаёт вердиктов «плохо сыграл». Показывает число, из чего оно сложилось и от чего отличается.
- Не считает вклад в победу. Для этого нужны данные о файтах поминутно, которых нет.
- Не сравнивает игроков разных ролей одним числом без явной оговорки, что веса у ролей разные.

## Тесты

`src/features/scoring/*.test.ts`, обязательный минимум:

- перенормировка весов при выпавших частях
- `q()` на границах: ниже p50, ровно p50, ровно p90, выше p90
- деление на ноль при `T = 0` и при пустой команде
- восстановление смертей из `kills_log` соперников совпадает с итоговым `deaths`
- при `T` = конец матча оценка отличается от посчитанной по `benchmarks` не больше чем на 8 пунктов на выборке из 20 реальных матчей
