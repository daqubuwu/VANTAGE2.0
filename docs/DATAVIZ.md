# Шкалы для графиков

Дополнение к `docs/DESIGN.md`. Пишется перед первым линейным графиком (тренд формы), правила распространяются на все следующие.

## Общие правила

- Один визуальный язык на весь сайт: SVG от руки, без графической библиотеки. Причина - на сайте пока три вида графика (heatmap активности, линия тренда, позже полоса преимущества в матче), для такого объёма зависимость не нужна.
- Ось Y подписывается только на границах и на 50%, если шкала процентная. Промежуточных линий сетки нет - лишний шум при `VISUAL_DENSITY` этого проекта.
- Подписи оси X - не чаще, чем раз в 4-6 точек, дата в коротком формате (`num.num`).
- Каждая точка кликабельна и наводима: тултип `hint` с датой и значением на всех графиках, `math` - только там, где значение производное (тренд формы).
- Точки с низким доверием (мало игр в окне, матч не разобран) рисуются полым маркером (`fill: var(--surface)`, `stroke` цвета серии) и не считаются частью сплошной линии по смыслу, только визуально не выпадают из ряда.

## Цвет

Ровно два приёма, оба уже описаны в `DESIGN.md`, здесь - как применять на линии:

**Смысловая шкала (для метрик типа "хорошо/плохо" - винрейт, тренд формы, преимущество команды).**
Линия красится по значению каждой точки, не одним цветом на весь график. Интерполяция `--loss -> --ink-3 -> --win`, ровно как задаёт `DESIGN.md`:

```
0.0  -> --loss   #e54b52
0.5  -> --ink-3  #616a73
1.0  -> --win    #37bb62
```

Линейная интерполяция в RGB между соседними опорными точками. Реализация - `src/features/player/chartColor.ts`, функция `winrateColor(value: number)`.
Технически цвет линии - `linearGradient` вдоль оси X с `stop-color` на каждую точку данных (не два узла, а по узлу на точку), потому что цвет несёт данные каждой точки, а не общий тренд слева направо.

**Заливка площади под линией.** Отдельная от цвета линии, вертикальный `linearGradient` одного акцентного цвета (`--accent-hi`) от 22% прозрачности сверху к 0% внизу. Заливка не несёт смысловую окраску - она просто даёт объём, поэтому не красится по значению. Комбинация "цветная линия + нейтральная акцентная заливка" - осознанный выбор: смешивать оба смысла в одной заливке (RGB × alpha по двум осям) SVG не умеет без масок, а маски - лишняя сложность для линии из одного графика.

**Нейтральные графики (пока нет).** Если появится график без "хорошо/плохо" (например чистый объём золота во времени), линия и заливка красятся одним `--accent`, без интерполяции по значению.

## Геометрия

- Высота графика тренда - 120px, без подписи по Y кроме 0/50/100%.
- Толщина линии 2px, точки - круг 3px, полый маркер - круг 3px с обводкой 1.5px.
- Скругление линии - `stroke-linecap: round`, `stroke-linejoin: round`, сглаживание сплайном не делается: данные дискретные (одна точка на матч), кривая Безье через реальные значения искажала бы их - используется прямой полилайн.
- Появление графика - как в `DESIGN.md` про движение: `opacity 0→1`, один раз при входе в вьюпорт, без анимации самой линии слева направо (это уже "кинематографично" для аналитического экрана, `MOTION_INTENSITY 4` этого не разрешает).

## Что не делается

- Нет тултипа-кроссхейра, который двигается за курсором по всей ширине - это паттерн трейдинговых терминалов, для сайта с точками раз в матч он ложный: между точками нет промежуточных значений для интерполяции курсора.
- Нет анимации счётчика при смене периода - смена периода перерисовывает график целиком (это выбор данных, не операция над одним и тем же рядом).
- Нет второй оси Y и наложения двух метрик на одном графике - если понадобится сравнить два ряда, это два графика друг под другом с одинаковой шириной, не совмещённые.
