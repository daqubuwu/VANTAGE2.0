Слой 1, баги - разобрано и сдано:

- [x] «Способности и таланты» на странице матча иногда не показывал вообще ничего. Причина: `MatchPage.tsx` строил данные по talents сразу, без состояния загрузки - пока справочники OpenDota (`hero_abilities`, `ability_ids`, `abilities`) ещё не пришли, `build.talents` у каждого игрока получался пустым, и блок для всех тихо схлопывался в `null` без всякого сообщения. Добавил skeleton на время загрузки, ErrorState с повтором при ошибке справочников и явный EmptyState, если данных по конкретному матчу действительно нет (а не просто ещё не подгрузились).

## Как проверяется работоспособность

В облачном контейнере нет доступа к api.opendota.com, поэтому живые данные там не проверить. Вместо этого:

1. `npm run build` и `npm run test` обязаны быть зелёными.
2. Сборка поднимается в headless Chromium, запросы к OpenDota подменяются фикстурами (`scripts/shot-mocked.mjs`), снимается скриншот и читаются ошибки консоли.
3. Проверка на живых данных — на твоей машине через `npm run dev`.

Так уже поймана одна ошибка: кэш в IndexedDB падал с `DataCloneError`, потому что в дамп попадали ещё не завершённые запросы. Исправлено в `src/main.tsx`.

Вторая пойманная так ошибка, после итераций 5-7: три пары файлов в проекте различались только регистром первой буквы при одинаковом остальном имени (`BanSuggestions.tsx`/`banSuggestions.ts`, `TimingWindows.tsx`/`timingWindows.ts`, а также более старая `ItemSlots.tsx`/`itemSlots.ts` из итерации 3). На Linux-контейнере, где идёт сборка и тесты в этой среде, это два разных файла, и `tsc`/`vite build` проходят чисто. На Windows файловая система не различает регистр в имени файла, поэтому `tsc` увидел коллизию и билд упал с `TS1149`/`TS1261`. Правило на будущее: не называть логику и компонент в одной папке именами, различающимися только регистром - используется тот же приём, что уже был в `features/hero` и `features/meta` (`matchups.ts` + `HeroMatchups.tsx`, `tierlist.ts` + `HeroGrid.tsx` - разные по смыслу имена, не только по регистру). Файлы переименованы: `banSuggestions.ts` → `bans.ts`, `timingWindows.ts` → `timing.ts`, `itemSlots.ts` → `itemSlotFields.ts`. Отдельно всё ещё нужно было `npm install` после итерации 3 - `html-to-image` был добавлен в `package.json`, но не попал в уже установленный `node_modules` на твоей машине.
