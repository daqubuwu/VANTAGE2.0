Реалистично 7-9 итераций до состояния «заметно лучше прототипа». Дедлайна нет (ответ 11.1), поэтому темп определяется лимитом.

Переключение модели по фазам (согласовано в 12.2):

| Фаза | Модель | Effort |
|---|---|---|
| Ресерч, архитектура, дизайн-система, формула оценки | Opus 5 | High |
| Массовое написание компонентов, перенос функций, правки | Sonnet 5 | Medium |

Внутри одной сессии модель фиксирована настройкой приложения. Переключаю то, чем управляю: подагентов на объёмных механических задачах и глубину рассуждений. Если предстоит итерация целиком из механической работы, скажу перед стартом, чтобы переключить на Sonnet вручную.

## Как проверяется работоспособность

В облачном контейнере нет доступа к api.opendota.com, поэтому живые данные там не проверить. Вместо этого:

1. `npm run build` и `npm run test` обязаны быть зелёными.
2. Сборка поднимается в headless Chromium, запросы к OpenDota подменяются фикстурами (`scripts/shot-mocked.mjs`), снимается скриншот и читаются ошибки консоли.
3. Проверка на живых данных — на твоей машине через `npm run dev`.

Так уже поймана одна ошибка: кэш в IndexedDB падал с `DataCloneError`, потому что в дамп попадали ещё не завершённые запросы. Исправлено в `src/main.tsx`.

## Известные ограничения этой среды

- На компьютере не поднялась локальная Linux-среда, поэтому команды там выполнять нельзя. Сборка и тесты идут в облачном контейнере, готовые файлы кладутся в папку `Vantage2`.
- Для локального запуска на компьютере нужен Node.js 20+. Проверить: `node -v` в PowerShell. Если нет — https://nodejs.org, LTS.
- Заливка на GitHub — руками (ответ 9.1).
