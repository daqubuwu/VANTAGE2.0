## P2. Зависит от данных

| Функция | Данные | Риск |
|---|---|---|
| Лайв-матчи с win probability | OpenDota `/live`, Stratz live | Стрим нестабилен, вероятность считаем сами по золоту и составу. Обязательно подписываем, что это оценка |
| Heatmap перемещений по карте | OpenDota, поля есть только у распарсенных матчей | Работает не для всех игр, нужен явный пустой стейт |
| Детект смурфов и бустинга | возраст аккаунта, скачок винрейта, разброс метрик | Только как «признаки», без ярлыка «смурф». Показываем факты, вывод оставляем игроку |
| Страница патча: что изменилось и как ударило по винрейтам | нет прямого источника чейнджлога через API | Нужен парсер `dota2.com/patches`. Отдельная задача, минимум P2 |
| Поворотные моменты матча на таймлайне | `objectives`, `teamfights`, `gold_t` | Формулируем как факты: «рампага на 34-й, преимущество перевернулось на 12k». Без выдуманных причин |

## Про «ИИ» в этом проекте

Ответ 4.1 — вариант Б. LLM в рантайме нет, денег и ключа нет, всё считается в браузере.
Это значит: разбор матча и оценка игрока — детерминированные правила поверх статистики, а не генерация текста.

Практически:
- Оценка игрока: взвешенная модель по метрикам, откалиброванная на перцентилях бракета. Формула лежит в `docs/SCORING.md` и открыта пользователю через тултип `math`.
- Разбор матча: набор правил вида «условие на данных → фраза с подставленными числами». Каждое правило имеет порог, срабатывает не всегда, ранжируется по силе отклонения. Показываем 5 сильнейших.
- Тексты пишутся сухо и с числами. Требование из ответа 3.3: без «иишного вайба». Фраза без числа в разборе не показывается.
- Нигде не пишем «ИИ проанализировал». Пишем, что и как посчитано.
